## 性能实测

环境：Windows、Intel i5-13600KF、20 逻辑处理器、Node 24.22.1、pnpm 11.25.0、Playwright 1.64.1、Headless Chromium **156.0.8078.4**。Playwright 启用 `--enable-precise-memory-info` 读取页面堆采样，未启用 CPU 降速。这些是本机单轮样本，不是所有设备保证，也不是中位数/P95。

| 数据与操作 | 本轮耗时/结果 | 口径 |
| --- | --- | --- |
| 100,002 条普通词条、两个词库 | 样本建立 **3,072.5 ms** | 原生 IndexedDB 单事务构造测试数据，不等于资源中心文件导入速度 |
| 月亮邮差、多词库联合索引查询 | 冷 **25.1 ms**，同 Worker 缓存 **0.9 ms** | 包含 Worker 冷启动/消息/数据库；两条真实命中、完整拆分；不含结果 DOM 绘制 |
| 词099999（深位置条目） | **23.1 ms** | text B-tree 查询，无 offset；不是旧生成器 seed offset 的基准 |
| 修改月亮→太阳且版本变化 | 查询只剩邮差，cacheHit=false | 真实 IndexedDB 事务和生产 Worker，非缓存单元模拟 |
| 正在扫描的拼音查询取消 | 扫描 **256** 条后 terminate 调用 **0 ms**（计时精度内）；150 ms 无迟到消息 | 不承诺线程释放/取消延迟严格为零 |
| 10,000 行关系文件导入 | **2,390.9 ms** | 生产资源 Worker、真实 IndexedDB、新关系字段/索引 |
| 10,000 结果生成并持久化 | **439.3 ms**；最大批次 64；全部左右行内绑定正确 | 原审计浏览器用例重新执行；参考旧 4.65s/0.83s 无时间回归迹象，非统计显著性检验 |
| Node 百万潜在组合取 10,000 | **57.16 ms** / 40,041 步 / 最大批次 64 | 原真实执行器 + 虚拟源，非数据库/浏览器 |
| Node 扫描 100,000 重复候选 | **66.41 ms** / 200,002 步 / 1 个唯一结果 | 输出去重回归，非词库导入 |

100,002 条样本建立前/后主线程 sampled usedJSHeapSize 为 **9,835,540 / 7,253,125 bytes**。后值低于前值受 GC 和采样时机影响，**不能解释为导入减少内存**。这是主线程两点采样，既不是峰值，也不含 Worker 堆、IndexedDB 内部缓存或完整浏览器 RSS；Worker 峰值指标当前未获取。不能据此关闭 Q01。生产样本只有两条命中（观察到批次 2）；50 条上限另由 500 命中自动化用例验证。

采用现有 B-tree 片段探测和 keyset 扫描已有测量支持，没有证据要求本轮建立全库 Trie/n-gram 或进行大规模表重构。对百万关系、低端机器、冷磁盘、跨浏览器和大型 JSON 峰值的性能仍未知。

## 开发中发现与修复

- 游戏规则模块初次接入时与 model 发生初始化循环，导致规则默认参数类型错误；将既有 Unicode 函数移入无模型依赖的 unicode.ts，model 保留兼容导出；新 graph/AST/分享测试确认修复。
- 结果上限检查发现缓存命中也必须分批，已统一为最多 50 条；首查与缓存均覆盖。
- 已保存模板的分析补全全局节点上限 20 和总预算 10 秒，避免工作流多模板导致不受控工作量；有限分析不升级成“真实来源”。
- 结果存为词库的异步错误现在可见，解决审计 U05 的反馈缺口。schema、关系属性、脚本和旧配方兼容都由实际回归确认。
- 开发中有一条 AST 测试使用了项目不支持的 for/emit 语法，已修正测试构造；未把测试构造错误算成产品缺陷。

## 结论和未解决风险

本轮要求的关系方向阻断已解决，P1-C1～C4 在文档明确的资源/搜索/模板预算内完成并通过上述验收。**建议可进入 P1-D**；没有提前实现新动画。

仍保留：历史 runs 快照持续增长（U02）、原生成器种子旋转及资源编辑深页 offset（U03）、整体 JSON 解析与导出 Blob 峰值（U04）、空库错误类型的执行前校验不足（U06）、低性能/跨浏览器/reduced-motion 与完整 E2E 矩阵。拼音默认读音、20 模板/200 输出的有限推断、10,000 拼音扫描、500 词条命中均可能造成遗漏，界面披露边界；任何遗漏不能用伪造来源补齐。P1-C 通过不代表整份 v3.0 产品规划、Q01/Q02/Q03 或完整 P1 都已完成。
