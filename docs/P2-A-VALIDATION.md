# P2-A 参数化子图与可复用函数验收

日期：2026-10-31（Asia/Shanghai）。起点 `21e0b67`，开发分支 `codex/p2-a-subgraphs`；保留起始用户文档、P1 审计、关系冲突修复与未跟踪文件。设计和支持语法见 [架构定义](P2-A-ARCHITECTURE.md)。

**结论：P2-A1～A5 在下述单返回序列函数支持矩阵内 GO，可以进入后续 P2 子阶段；完整 P2 和更广泛函数能力仍未完成。** 本文只记录 P2-A 的单返回序列函数范围，不表示整个 P2、全部函数形态或 v3.0 产品规划完成。

## 分阶段支持矩阵

| 阶段 | 实际实现 | 验证入口 / 边界 |
| --- | --- | --- |
| A1 定义与调用 | 稳定 ID/version/显示名；显式序列及 string/number/boolean 参数；默认值、必填；单返回节点；独立作用域、静态资源依赖、DAG、12层限制 | subgraphs.test.ts；序列不隐式转换成 AST 标量/集合/Pair；禁止捕获与递归 |
| A2 画布执行 | 选择已连线节点封装，识别边界；配置接口、重命名定义；添加内部节点、序列参数、嵌套调用；返回节点选择、面包屑、保存、空子图、复制定义、添加多个独立实例 | subgraphs.spec.ts 实际操作；真实词库/前缀/模式/输出；保存产生新版本，其他工作流固定旧版本 |

用户入口：主画布底部 **子图与函数**。选择不含 output、只有一个出口的节点，点击 **封装所选节点**；编辑内部节点后选择要返回的节点，选择标量字段并暴露参数，保存返回，再回主图配置调用参数/序列输入并连接结果输出。

## 发现并修复的 watchdog 边界

首轮完整 Chromium **30/31**，原28项全通过，新阻塞超时用例失败：[首轮日志](p2-a/browser-first-full.txt)、[首轮JSON](p2-a/browser-first-full-results.json)。这不是通过延长测试阈值解决的。

定向消息探针显示 Worker 定时器约10028ms触发，但旧代码等待 `finishRun()` 完成后才发送error；资源读事务阻塞时，终态写入也排队，调用者因此收不到超时通知。[红灯](p2-a/watchdog-red.txt)、[定时器探针](p2-a/watchdog-probe.txt)。修复将超时通知置于持久化之前；App原有终止/终态重试保持，Worker抑制重复终态通知。探针已从生产源码删除。修复后定向 **3/3**，约10029ms终态error且保留128条；随后全量33/33通过，最终时间和数量见watchdog.json。

## 性能与内存边界

300调用基准不是预先创建百万候选数组：生成器声明百万逻辑条目，实际拉取201条即在第二个唯一组合处达到顶层limit=1。定义只存小型节点和依赖，不存候选/资源内容；无跨实例候选缓存。单元同构基准及浏览器样本分别记录，不能以两种耗时直接比较。

峰值工作集包括活跃异步迭代器、调用标量/小Map、每个资源reader最多256行分页、已有group/字典缓冲、最多10000个输出去重键与64条背压批次。资源重放可能重复查询分页，代价随图组合增长，并最终受共享预算限制；不保证所有多调用图都只读一次。100外部调用用满主图200节点上限，多层依赖另受12层、100定义/2000内部节点约束。

浏览器性能报告的 heapSamples 是主线程 JS 堆离散采样，只验证该夹具采样增量低于64MiB；不是 Worker、GPU、RSS或全程峰值，也不是普遍64MiB总内存承诺。真实低端、Firefox/WebKit、全部复杂图的峰值仍归Q01/Q02，不因本轮数字而关闭。

## 保留限制与后续准入

- 当前函数返回单一序列；用户标量函数、Pair/集合返回、多返回端口、递归、高阶函数、闭包和任意JS/TS不支持。已有program内部控制流独立使用，不捕获函数参数。
- 封装器只接受单一出口且不含结果输出的选择；通过边界序列参数显式连接。参数编辑界面支持常量与默认值；复杂的嵌套参数转发可通过受支持的fn代码配置。
- 已有显式绑定参数的重命名、增删必填端口等破坏接口的修改，目前需要复制定义并添加/连接新调用；发布时拒绝无效旧调用，尚未提供自动参数迁移向导。内部program可保留、执行并通过NameScript编辑，子图面板暂未接入独立program结构编辑器。
- 发布内部修改会留存旧版本，并只更新当前主图的直接调用；嵌套版本需显式编辑。没有自动版本合并、历史版本回收或大型依赖可视化面板。
- 草稿可自动保存，发布和运行前严格验证；子图库写入与主工作流自动保存属于两个独立数据库事务，断电时不承诺跨库原子提交。嵌入工作流的定义使正常运行不依赖子图库可用。
- 资源历史仍无内容快照；新运行读取当前绑定版本。旧来源保护遵循S0-1；不宣称任意历史可重放。
- 整体JSON分享大小、资源深页、Entry迁移、动态词库、扩展包、社区、PWA及原G01～G09/Q01～Q03的其他缺口继续保留。

本轮只为上述序列子图闭环建立准入证据。后续可以在固定调用/依赖契约上扩展资源依赖或更丰富函数类型；不能把本轮范围称为整份产品规划完成。
