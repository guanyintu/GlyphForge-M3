# P2-C：动态词库与独立 Mapping

日期：2026-10-31，Asia/Shanghai。基于 P2-B `ca76906`，不重做 P2-B。验收及范围判定见 [P2-C-VALIDATION](P2-C-VALIDATION.md)。

## 资源契约和 DAG

复用 `Resource.id/kind/version`。旧静态 word/character/symbol/relation 记录不重写；无 definition 表示静态存储适配。新增 `kind=mapping` 及可选 definition：`{format:1,type:mapping,rules}` 或 `{format:1,type:dynamic,workflow}`。显示名称不参与内容键；静态行写入、规则/动态定义写入增加内容版本，定义编辑带 expectedVersion，拒绝覆盖静态资产或并发编辑。

先实现 [resource-catalog](../src/core/resource-catalog.ts) 和专项测试，再接 UI。固定 ID 引用形成 DAG；12层/100资源上限，DFS active/done 分离，返回带路径的循环/缺失错误，菱形只记录一次源版本。定义中的参数化资源 ID、运行时计算的资源依赖不开放；所有子图定义和 program 字面量依赖都纳入检查。普通主图的动态资源 ID 原有能力不扩展。

源版本向量是整个传递闭包 `{id:version}`。精确签名为格式/算法版本、排序后的 ID/kind/version/definition，加调用种子；使用完整 JSON，不依赖易碰撞的短哈希。定义和 Mapping 内容在运行记录 `resources/resourceKey` 保存，便携包另带静态实际行。普通历史仍不复制任意大静态词库，因此不承诺删除源后重放旧运行。

## 懒执行、一致性和预算

`engine.evaluateWorkflow` 是从原执行器提取的同一异步候选解释器；顶层 `execute` 继续去重、批量输出、保留来源和原预算。动态资源不创建新运行、不重置计步器，执行时使用外层种子及共享 tick，可包含既有中文、关系模板、program、P2-A子图和P2-B变异算子；只允许输出普通候选，Pair 必须经模板/AST显式投影。

`resourceSession` 固定一个元数据/定义快照；启动、资源读取、每64候选及结束检查整个传递版本向量。生产 Worker 启动时比对 beginRun 的向量；每批写入与 done 的版本检查位于包含 resources 的同一个 IndexedDB 事务中。发现编辑/删除即报错，之前已提交的部分结果仍带原版本且运行标为 error；不得标记成成功的混合版本运行。不会在中途自动重绑新源。

不物化动态全集，不做全局/持久候选缓存；每个迭代器按需执行，静态页256行、顶层批次64。精确 key 留作预览失效和将来缓存契约，当前没有迟到任务可以污染的共享候选缓存。动态单次读取最多定义 workflow.limit（1–10,000）候选，重复候选计入这个上限；最终消费者 output 去重。逻辑笛卡尔积可以百万级，实际工作仍受300,000共享步骤/10秒/1024文字代码单元等原契约限制，不承诺枚举百万结果。

预览独立 Worker，每页60条，深页重放跳过前缀，最多167页/10,000候选，达到步数/时间限制明确失败。切页、源版本变化、关闭和取消终止旧 Worker；消息需匹配当前 Worker 身份。源变化清空旧页，用户点击重算；不在后台悄悄把另一版结果替换进当前运行。既有执行 UI 的硬取消/watchdog、背压与留存继续生效。内存界限来自页/批次、图/依赖深度、定义大小和候选/文字上限；本轮没有完整 Worker/RSS 峰值测量。

## Mapping 的共用语义

Mapping 复用 P1-A `parseCharacterMap` 与 `transformChinese(mapchars)`：最多16,384代码单元、256个单码点键，每键1–32个候选，每候选最多64代码单元；空对象为恒等映射。采用现有字符簇处理、候选组合顺序、概率与种子语义。不是任意正则、脚本、分词或多字最长匹配规则。

mapchars、hanconvert、mutate 增加可选 mappingId。非空时必须解析为 Mapping 资源；空值沿用旧 JSON/内置火星文。中文节点/文字实验室/图级NameScript/program AST经同一解析与转换器执行；变异器的火星文替换经同一 mapchars 转换，按原变异选择规则消费候选。资源引用优先于内联字段；原字段仍按原契约校验。转换记录真实 Mapping ID/version/输入片段，变异记录父来源；不伪造旧运行身份。

UI 在资源中心创建、命名、编辑、导入导出 Mapping；中文参数和变异器可选引用。动态编辑器提供「源→Mapping→前缀」快捷组合、当前工作流定义和 NameScript 编辑，支持关系模板投影及既有子图。依赖列表显示上游与源版本，静态/关系/定义编辑器显示保存的下游资源和工作流警告。删除保留下游定义以呈现缺失错误，不级联删除资产。

## 存储与分享

保持主库 schema6 和子图库 schema1，新增字段为加法；没有升级全局 Entry/Membership，没有迁移/删除已有静态行、关系、收藏、工作流或历史。旧 v1–v5 分享路径保留，旧内联 Mapping 继续可运行。运行备份 v1 的附加资源快照字段可往返。

有定义资源的工作流导出 v6（IR1、resourceDefinitionVersion1、算子版本、传递依赖清单、定义和所选静态行）；无定义资源继续用旧版本。资源编辑器默认导出整个传递闭包；分享面板展示传递依赖并允许勾选。静态快照每库十万行、100资源、包大小有界；定义不展开为结果行。独立 Mapping 使用 `glyphforge-mapping/version1` 文件，导入重分 ID。

v6 导入先校验全部定义/行/清单/DAG/算子版本，再统一映射新 UUID，重写主图、子图、动态定义、模板和 program 的引用；一次事务写资源/行/工作流，任何错误回滚。不会覆盖同 ID 本地资产。轻量包可绑定类型兼容的本地源；动态本地绑定还要求其依赖闭包与清单一致，不推断两个不同动态 DAG 等价。

## 本轮边界

没有自动持久增量索引/物化缓存、全局Entry迁移、多词最长匹配Mapping、可视化任意DAG编辑、资源级历史撤销或静态历史内容归档。动态结果不加入逆向词条B-tree，需先存为静态词库；真实已生成来源仍可查询。源修改在下次读取时报失效，预览显示等待重算；不是后台持续订阅计算系统。P2其余规划及既有G/Q缺项继续保留。
