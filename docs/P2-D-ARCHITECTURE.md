# P2-D：可信声明式算子扩展与版本注册

日期：2026-10-31，Asia/Shanghai。基线 `4633833`（P2-C GO），分支 `codex/p2-d-packs`。本阶段沿用 P2-C，不重新实现动态资源。验收见 [P2-D-VALIDATION](P2-D-VALIDATION.md)。

## 协议与身份

[packs.ts](../src/core/packs.ts) 定义 `glyphforge-operator-pack / protocol=1`。包具有稳定 `id`、精确三段版本、发布者、来源标签、`compatibility={ir:1,contract:1}`、依赖精确版本、迁移清单、零权限、确定性和增量执行模式。兼容范围当前为 IR/契约 `[1,1]`，没有猜测应用版本兼容性或解析 `^`/`latest`。

算子全限定 ID 由 `packId@version/operatorId` 唯一确定；operatorId 不允许占用任何现有内置 Op。内置 `extension` 只是固定协议适配节点，不能被外来包替换。每个声明算子是单 `CandidateSequence` 输入与输出；参数用 S0-2 的 string/number/boolean 类型、显式默认值及有界值。节点序列化参数为 `pack/version/operator/values/mappingId`；`values` 是 JSON 数据，不是表达式或代码。

工作流的 `extensions` 保存完整声明；运行记录原样保存工作流和动态资源定义，因而保存了使用的算子内容与版本。纯核心解释器可直接执行已验证的快照；生产执行、预览及持久化入口另外检查本地安装/启用状态。不同版本可并存，同版本不同内容拒绝；缺失/禁用不会删除节点或修改历史结果。当前没有自动版本替换。

`migrations` 仅声明来源精确版本、同一 operatorId 及参数重命名。用户在节点设置明确点击迁移，随后重新验证目标参数；新参数使用目标显式默认值。无迁移路径或降级路径时显示错误。历史工作流仍保存旧声明；不批量重写其他工作流。内部子图不开放扩展身份或 JSON 参数的动态标量绑定，序列输入正常组合。

## 执行与安全边界

所有包（含第一方）当前均使用可审查的声明式流水线，最多16步。白名单是 `prefix/reverse/filter/mapchars`，步骤参数通过原 `normalizeParams` 验证，图执行直接组合原 `operatorRegistry` 异步迭代器；不另建结果生成器。两个真实扩展类型为有界文字框架（支持 Mapping 和 Unicode 倒序组合）及组合过滤（包含、排除、字符长度）。第一方 1.0.0/2.0.0 随源码发布，2.0.0 演示 prefix→opening 的显式迁移。

| 入口 | 支持与限制 |
| --- | --- |
| 图 / 生产 Worker | 支持；共用 S0-2 参数、错误定位、取消/背压/步骤/时间/文字预算 |
| 图式 NameScript | `extension(sequence, pack, version, operator, valuesJSON, mappingId)`；沿用已有解析器，base 工作流携带声明 |
| P2-A 序列函数 / 子图 | 支持显式序列参数，函数打印/解析和节点剪贴板携带声明；子图库存储声明，不隐式安装包 |
| P2-C 动态资源 | 支持；资源图依赖、版本、静态快照与 Mapping ID 重绑定沿用 P2-C |
| P2-B 变异 | 扩展输出可继续创作；动态资源内的扩展可作为词库替换源；变异继承原父来源边界 |
| program 标量 AST / 实验室 | **不适用**；没有声明标量函数签名，不伪造无损转换。实验室白名单不展示 extension |

单输入文字变化继续通过原 `candidateText`/中文转换器清除失效 Pair/members；原 parts/notes 保留，Mapping 增加真实来源，过滤不伪造来源。固定种子、精确声明、资源内容版本和内置数据版本构成复现条件；UUID 重绑定后文本可复现，资源身份仍按导入后的真实 ID 记录。旧静态资源任意历史内容缺失、跨 ICU 的限制继承 P2-C。

没有 eval、new Function、用户模块导入、脚本字段、任意正则、任意网络/文件权限。`publisher/source` 只显示为文本，不请求 URL。第一方可信标识由声明与随代码发布的对象逐字内容比较得出，JSON 不能自报 trusted=true。未知发布者可安装，但默认禁用；用户可以明确启用其受限声明，启用不会把发布者改成可信。

| 威胁 | 实施限制 |
| --- | --- |
| 压缩炸弹 | 安装仅接受未压缩 JSON；无解压路径，128K文件门限先于读取；分享仍有原15MiB门限 |
| 嵌套/巨大声明 | JSON深度20、12000值、保守128KiB代码单元预算；32个包版本、每包16算子/16参数/16步骤/16依赖；调用参数JSON最多8192字符，单标量字符串256 |
| 依赖循环/放大 | 精确版本DAG，active/done检测，最多12层；不执行依赖的任意入口，不支持扩展递归或动态代码加载 |
| 原型污染 | 递归拒绝 `__proto__/prototype/constructor`；字段白名单、纯JSON值、保留ID、类型检查；先验证再事务写入 |
| 隐藏资源引用 | 包不能硬编码 Mapping ID；引用由节点显式 mappingId 端口传入，纳入已有资源DAG和分享重绑定；values 内的非空 mappingId 拒绝；URL形态的未知ID只会缺失报错，不会请求网络 |
| 权限/同名覆盖 | permissions必须空；未知包/步骤字段和内置ID遮蔽拒绝；已安装同ID/版本不同内容拒绝 |
| 运行中禁用/卸载 | Worker启动、动态读取、批次提交及done检查；批次/done的检查与写入共用包含extensionPacks的IDB事务；保留此前有效部分结果，不能提交无效终态 |

安装和运行的校验使用相同声明。引擎预算不因步骤/子图/动态资源重置：300k步骤、10秒、10k输出、64条批次、1024代码单元/文本。流水线消费惰性上游，不物化逻辑组合全集；注册表/节点/声明本身有固定大小限制。

## 本地资产与分享

主数据库 **schema6→7** 仅新增 `extensionPacks` 表（key=`id@version`，保存 manifest/enabled），不重写原资源、关系、工作流、收藏和历史。安装检查全部依赖及本地冲突；关闭依赖允许发生，使用者会显示缺失/禁用提示。UI 可查看声明、兼容状态、依赖、来源、参数与适用入口，支持安装、启停、卸载、导出声明、选择真实算子及明确迁移。

使用扩展的主图或传递动态定义导出 **v7**，复用v6资源包结构，并携带必要的 `packManifest`；依赖包取实际扩展节点的传递闭包，不要求未使用的禁用旧版继续启用。导入验证 manifest 与工作流/动态定义一致，先做资源DAG/算子契约检查，再在一次 IndexedDB 事务写入包、资源、词条、关系和工作流。资源ID继续重分配，扩展精确全限定ID保持不变；内容冲突或任何写入失败全部回滚，不能覆盖本地资产。已有包的 enabled 状态不因导入改变；新导入的未知包默认禁用，匹配内置内容的第一方包可启用。

没有扩展继续使用既有v1–v6读写路径。旧格式中夹带扩展声明不被解释为旧包升级；扩展要求v7。v7不包含可执行外来代码，也不包含收藏/历史全集；收藏和结果文件/运行备份继续沿用已有入口。

## 自定义代码节点的将来隔离路径

自定义JS节点本阶段保持关闭。普通同源 Worker 能访问网络、同源存储和其他 Web API，只承担计算与取消隔离，**不是恶意脚本安全沙箱**。攻击者可能窃取资产、联网外传、滥用CPU/内存、污染持久存储或通过消息冒充受信结果。

未来路径需另行验收：独立隔离源或受限进程，禁止访问应用origin/凭证/IndexedDB、默认拒绝网络及文件能力、严格CSP/权限策略、固定可序列化输入输出和消息能力令牌、宿主校验输出、独立CPU/内存/墙钟限额和强制销毁、无默认持久权限。浏览器CSP及Worker不能单独证明隔离成立；应以跨源逃逸、网络外传、存储访问、消息伪造、死循环/内存耗尽攻击测试及供应链审查作为开放前门槛。本阶段没有实现或启用这条路径。

## 范围

这是可信第一方与受限声明式组合协议，不是通用第三方脚本插件生态。没有在线市场、签名分发/撤销、自动升级、任意DAG包、第三方标量AST扩展、实验室动态注册、压缩分享码或脚本沙箱。跨浏览器、真实低端和完整Worker/RSS峰值及长期安装规模仍未验收；P0/P1及P2-A～C的历史G/Q边界继续保留。
