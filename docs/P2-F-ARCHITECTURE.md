# P2-F：只读规模估算与纯计算复用

日期：2026-10-31，Asia/Shanghai。基线 `9f4087a82de4b284d022ebf7d3e6af0c346701e4`。范围、实际数字和真实失败见 [验收](P2-F-VALIDATION.md)。

## 决策

**减少枚举次数的规则 NO-GO。** 直积内层的重复读取、版本核验、tick、随机消耗和错误位置都是当前可观察执行语义。跳过前缀或把过滤移至资源读取之前会改变这些事件。没有证明可安全减少枚举次数的规则，本轮不实现、不声称高级枚举剪枝。继续使用原 `execution.worker.ts → execute/evaluateWorkflow → operatorRegistry`，子图、动态资源和扩展继承原预算，没有第二套生产执行器。

测量显示不同图有不同瓶颈：全拒绝静态直积主要等待资源读取；10k 全输出主要等待 IndexedDB 持久化；历史超过留存阈值时，清理也可能占据端到端时间。P2-E 的合并省略对高拒绝率有帮助，不解决数据库读取及持久化主导的问题。不能用一次百万逻辑空间的 60 项前缀耗时预测全量运行。

## 只读估算

入口为工坊「规模与执行风险（只读）」→「估算当前工作流」。未应用代码时禁用；结果对应当前节点图、种子、全部声明资源版本、Mapping 定义和扩展内容/启用状态。组件用有界元数据依赖查询监听变更，编辑后丢弃旧请求并重算；卸载/新请求用 AbortSignal 取消，过期请求不能提交 UI 结果。估算不作为运行前门禁，也不自动改工作流或 limit。

`storage/estimate.ts` 在同一只读事务读取资源/扩展元数据。只按 ID bulkGet 传递闭包，不扫 entries/relations，也不遍历整个资源目录；最多 100 个资源、12 层依赖。调用现有 planResources/图验证与扩展检查，拒绝循环、缺失、类型不符、深度超限、包未安装/禁用/内容冲突。计算前后再次取版本签名，变化拒绝发布；estimateIsCurrent 可在后续使用前重新验证。取消在每次读、计算访问和最终快照处检查，不承诺中断已经提交给 IDB 的单个请求。

精确静态 count 仅用于**去重前序列数量与直积数量**。乘法使用 BigInt，返回十进制字符串，避免 Number 溢出。concat/pattern 乘输入上界；prefix/reverse/output 保持基数；filter/gamecheck 降为上界。最终 unique 输出还会被 limit 截断，不能把去重前数量称为最终输出数量。字符串超限/预算错误可能阻止枚举完成。无效或不安全整数 count 返回未知；静态 count 本身依赖现有版本化写入契约，未通过昂贵扫描“核实”。

动态词库即使 count=0 也返回 `0–workflow.limit` 区间（exact=false），内部枚举未知，绝不当成空库。program、变异、中文扩展、多槽模板等未证明基数的算子返回未知；保留说明。子图显式绑定参数与序列输入，按定义作用域展开；最多访问 10000 次，超限返回未知。这里不执行动态工作流，也不计算通过率。最大局部直积不是总执行步数：共享节点可能重复读取，动态内部或未知算子可能有更大的工作量。

风险分为高、有界、未知。已知直积超过 300000/3 或候选上界超过输出 limit 提示高风险；这是解释性启发式，**不是步数下界、成功保证或耗时预测**。任何未知基数保持未知说明。界面同时展示最近完成运行的实际结果数、步骤、引擎耗时、截断与元数据省略计数；失败/取消部分结果不推断为完整规模。

## 两条局部规则与等价证明

`optimize=false` 关闭 P2-E 和本轮两条复用规则；此选项传递到动态资源和扩展流水线。没有候选缓存，没有资源内容缓存，也没有跨运行解析缓存。

1. **模式解析复用**：算子参数已经由原 normalizeParams 接受为 1–16 个 ASCII A/B。一次算子调用把每个 token 转成输入索引。原 `replace(/[AB]/g, callback)` 的第 i 次 callback 返回 a.text 或 b.text 的原字符串；新规则按相同索引选择并 join，逐个 UTF-16 代码单元相同，包括 `$&`、空字符串、组合字符、ZWJ、旗帜和 CRLF。仍在原组合 tick 之后、原 boundedText 检查点构造文字；不根据字符簇边界提前拒绝，不消耗随机数，不影响读顺序。模板参数绑定不同的调用各自解析，没有全局键污染。
2. **来源引用字符串复用**：原 traceCandidate 在每个真实 yield 计算 `JSON.stringify([scope,path])`，再调用 mergeLineage。新规则仅复用相同 scope/path 的不可变字符串，仍每次调用同一个 mergeLineage，保留其验证、32引用/4096单元上限、首出现顺序、incomplete 及新对象分配。scope 变化显式失效。缓存限单次 evaluateWorkflow、2048键和262144代码单元；达到上限即按原式计算，不改变输出。缓存不包含 Candidate、parts、notes、Pair、members、资源内容或随机状态，因此不需要也不允许跨种子、版本、Mapping、扩展或运行重用。

归纳：上游迭代和 tick 序列相同；每一同位置产生的 text 相同；来源字符串相同，合并函数未变；下游的过滤、稳定 text 去重与首路径选择因此相同。原有错误仍发生在相同 tick/文字检查处，节点诊断不变。代价变化会影响真实墙钟：10秒上限、用户取消或并发编辑发生在外部时间上，**期限前部分结果不保证完全相同**。差分使用固定步骤预算；时间行为单独报告，不隐去这一限制。

冻结 P2-E 前执行器沿用 p2e-legacy-*，本轮另冻结 P2-E HEAD 的 engine/operators 为 p2f-baseline-*，仅改测试 import 路径，[原始 SHA](p2-f/frozen-sources.json)。冻结副本仅供差分，不是新生产执行路径。

## 真实测量口径

Worker 可选 profile=true，在原执行路径记录 prepare、资源 next 的 readInclusive、text、metadata、filter、lineage、persistence、消息入队、终态持久化和历史清理。关闭 profile 的交替重复运行才是性能基线；采样本身有计时开销。动态 readInclusive 包含内部计算，与其 text/lineage 计时重叠，不能相加。静态图可给出剩余时间（迭代器、tick、调度、验证及计时开销），不伪称为精确枚举 CPU 自耗时。消息计时只涵盖 postMessage 序列化/入队，不涵盖主线程接收和渲染。

墙钟包含 Worker 启动、持久化、终态和留存；RunStats.duration 是引擎及批次回调耗时，二者分列。每个生成样本新建 Worker，模块/运行内缓存冷；同一浏览器/数据库重复执行后，IDB/操作系统页缓存可能热，不声称清除了磁盘缓存。逆向专用 Worker 保留实例，明确区分结果缓存 miss/hit 和源版本失效 miss。

审计生成夹具使用 Worker 自己建立 run 的既有入口（未传 runId），因而 Worker 自己执行留存；工坊 UI 的 managed-run 使用相同引擎/写入路径，由 App 在终止回调执行留存。这里的 done 墙钟不冒充 UI 首项呈现延迟，也不能直接代替 managed-run 的整页交互延迟。

Renderer V8 heap、专用 Worker 的 CDP Runtime.getHeapUsage 和进程 RSS 是不同指标。沿用生产 lineage 浏览器专项重新采样 Worker V8 堆，保存在本轮 replayed 证据中；它不是绝对峰值、RSS 或真实低端结果。本轮未获得可靠 Worker RSS。

## 兼容和延期

保持 schema7，无全局 Entry 迁移；不改运行、收藏、来源或便携 v1–v7 格式。旧 P2-A/B/C/D/E、S0-2 预算、取消、背压与来源面板继续回归。没有压缩分享码、任意 JS、网络插件、社区或新执行平台。

保留：枚举级剪枝、总步数/精确耗时模型、program/动态内部基数分析、跨运行缓存、源历史全集、同名多收藏、Worker RSS/绝对峰值、Firefox/WebKit、实物低端与历史 G/Q 差距。P2-E 的高级枚举剪枝条件**没有解除**；本轮估算与纯计算复用不代表完整 P2 或 v3.0 完成。
