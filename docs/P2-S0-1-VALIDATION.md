# P2-S0-1 运行留存与异常恢复验收

日期：2026-10-31，Asia/Shanghai。基线：`bc7966b` **加开始时尚未提交的 P1 最终审计修复**。

**结论：本阶段 GO，可以开始 P2-S0-2。** 本轮只解决 R01/历史 U02，没有实施类型契约、子图、函数、动态词库或其他新业务。P2 高级业务仍须等待 S0-2；整份 v3.0、G01～G09 与 Q01～Q03 的剩余目标继续保留。

## 实现与规则

- 复用 runs/generated/favorites，schema5→6仅加状态、`[retention+createdAt]`、favorites.runId索引与可选字段。已有v1～5依次迁移，不重建库；v2/v3单元、v5真实浏览器实测。
- 默认最近20次普通终态运行，可配置0～200。固定、收藏依赖及执行中的运行额外保留；成功/错误/取消/中断适用相同策略。为简洁与完整性，收藏保留整次来源运行。这些主动保护的数据仍可增长。
- 终态后自动裁剪，也可手动应用策略；恢复本身只标记中断，随后运行结束或手动清理回收超额记录。升级事务不裁剪，但应用沿用启动后自动生成，因此首次打开后的自动运行结束也会应用策略；需保留大量旧记录时应提前备份配置文件或导出。
- 裁剪按复合索引定位，每批最多16次；同一事务重新检查固定/收藏/执行状态，再通过runId索引删除generated和run。不会每次生成扫描所有历史、收藏或词条。失败批次回滚；此前已提交的清理批次不会自动恢复，重试可以继续。
- 批次与计数同事务提交，复合主键防重复。首次终态胜出，迟到批次拒绝；done只在完成状态落库后发出。UI在Worker启动前建立runId/记录，处理started前取消；Worker报错、UI的error事件和12秒硬期限均写入终态。引擎10秒预算、NameScript、节点/代码语义和分享格式未改。
- `glyphforge-run:<id>` Web Lock标识存活执行者。启动/刷新查询running索引，只有取得空闲锁才标interrupted；活跃其他标签页与后台页面不会被误回收。页面/Worker/浏览器退出自动释放锁；恢复不重跑、不重复写结果，保留已提交部分结果。
- 收藏切换与来源保护同一事务。旧收藏有run时从收藏自身补回此前被旧算法删除的同名generated；不伪造缺失的run或资源内容。迁移重新计算计数，未知旧状态标中断。
- 历史面板按需挂载，每页读取至多11次运行、显示10次；选定run每页读取至多51项、显示50项。状态、固定/取消、清理、策略说明及失败提示齐全。详情区显示工作流快照、资源版本号，以及当前资源缺失/版本变化。

实现：[生命周期](../src/storage/run-lifecycle.ts)、[schema](../src/storage/db.ts)、[Worker](../src/workers/execution.worker.ts)、[历史UI](../src/components/RunHistory.tsx)、[App](../src/App.tsx)。

## 迁移与恢复边界

升级在原生versionchange事务内完成，不删除资源、工作流、关系、预设或收藏。失败整体回滚，可释放空间后重试；浏览器实际中止过一次升级事务，再执行真实v5→6迁移，验证原数据可读。此项不是物理磁盘损坏/断电测试。schema6不能直接交给只识别schema5的旧应用，回退代码须保持schema6读取支持，不支持降级覆盖数据库。

逐次“导出运行备份”包含工作流快照、版本清单、已提交结果及该run收藏。恢复先验证格式和工作流，单事务插入，同ID run拒绝、同名收藏保留原值，自动固定恢复run；running备份转为interrupted。损坏/冲突不部分写入。单文件32MiB/10,000项，超限提示固定保留；这是单次运行备份，不是全库备份平台。

运行备份**不含完整资源内容**；独立恢复当前资源继续使用已有便携工作流包/词库导出。没有历史内容快照时不能保证完整重现任意旧结果。此前已经丢失的run无法补回；无runId旧收藏仍可访问并提示来源缺失。无法证明归属的孤立历史不猜测删除。无外部备份时无法应对整个配置文件/磁盘丢失。

收藏/固定数据额外增长属用户明确留存。本轮保证普通历史有界；已有收藏页面全量订阅和单次最多10k结果的内存模型沿用，巨型收藏与单次快照进一步分页/分片仍可优化。新增历史面板不会一次加载全部runs/generated。

## 存储增长与回收
