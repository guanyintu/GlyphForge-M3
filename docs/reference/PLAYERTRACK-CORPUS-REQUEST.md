# GlyphForge：FF14 全长度玩家语料分析与多风格中文 ID 词库建设

你现在负责 GlyphForge 的中文命名词库建设。

请直接检查当前项目架构，并在现有架构内完成一套基于 FF14 PlayerTrack 本地玩家名称数据的语料分析、词库提取和生成系统接入。

本次任务扩大语料范围：

**不再限制原始名称为 2～3 个汉字。**

2～3 字仅仅是「海都潮人」风格的目标输出长度约束。其他风格可以使用更长的名称、短语和组合。

核心目标：

1. 尽可能充分利用 PlayerTrack 的历史数据。
2. 提取有价值的单字、双字词、三字词、四字短语及更长的语义片段。
3. 建立多套风格不同、可以独立管理的词库。
4. 统计字符、词语在不同名称位置上的分布倾向。
5. 建立词语之间的语义和组合关系。
6. 让 GlyphForge 能够利用这些素材生成不同风格、不同长度的 ID。

不要只是把原始玩家名称批量导入词库。

## 一、数据来源与处理

优先读取本机 PlayerTrack SQLite：

Windows：
`%APPDATA%\XIVLauncherCN\pluginConfigs\PlayerTrack\data.db`

WSL：
`/mnt/c/Users/*/AppData/Roaming/XIVLauncherCN/pluginConfigs/PlayerTrack/data.db`

已知表：

- `players`：当前玩家名称，字段 `id`、`name`
- `player_name_world_histories`：历史名称，字段 `player_id`、`player_name`

要求：

1. 使用只读 SQLite 连接。
2. 当前名称和历史名称均参与统计。
3. 按 `(player_id, normalized_name)` 去重。
4. 不允许重复历史记录放大词频。
5. 保留名称原始长度，不得在数据读取阶段只筛选两字或三字。
6. 对不同长度的名称分别统计。
7. 保留繁体字和异体字，不要擅自转换。
8. 不导出玩家 ID、完整玩家名单及其他个人记录。
9. 只保留聚合统计和提取后的词库素材。
10. 不上传原始数据库或玩家记录到第三方服务。

主要语料：

- 纯汉字名称：完整纳入分析。
- 含数字、拉丁字母、符号的混合名称：独立统计，必要时提取汉字片段，不直接混入纯汉字词频。
- 特殊符号和装饰字符：单独建立素材类别。

## 二、名称长度分层

建立完整长度分层：

| 长度 | 处理方式 |
|---|---|
| 1 字 | 单字素材 |
| 2 字 | 完整名称、双字词 |
| 3 字 | 完整名称、相邻词片段 |
| 4 字 | 完整名称、双字和三字短语 |
| 5～6 字 | 完整名称、连续短语拆分 |
| 7～8 字 | 语义片段、短语拆分 |
| 9 字以上 | 长名称分析、短语提取 |

以上是分析分层，不是所有风格的生成限制。

必须提供：

- 各长度名称记录数
- 各长度不同名称数
- 当前名称和历史名称分布
- 各长度的重复率
- 不同长度之间的词语复用情况

注意：长名称不要简单按固定长度切片后全部加入词库。应当结合真实词语边界、语义和上下文提取。

## 三、六套独立风格词库

每套词库应有独立的素材、权重和组合规则。

### 1. 萌系日常

风格：可爱、轻松、亲近、自然，有一定网络感。

重点：

- AA 叠字
- 动物
- 食物
- 日常用品
- 口语
- 亲昵表达
- 可爱的短语

允许两字至六字甚至更长的组合。

### 2. 自然意象

风格：清新、空灵、有画面感。

重点：

- 天文
- 季节
- 天气
- 花草
- 山水
- 自然现象
- 时间与空间

提取完整词语和短语，例如月夜、春日、星野、听雨、山海等方向。

### 3. 清冷文艺

风格：简洁、克制、冷淡、有辨识度。

重点：

- 情绪
- 时间
- 抽象概念
- 文学意象
- 动作和状态
- 具有反差感的组合

允许较长的语义短语，不要只局限于两个汉字。

### 4. 奇幻角色

风格：FF14、幻想世界、异域感、角色姓名。

重点：

- 音译字
- 奇幻人物常用字
- 姓氏型前缀
- 中间连接字
- 名字尾字
- 种族和职业联想
- 长短不同的角色名称

支持两字、三字、四字及更长角色名。

### 5. 趣味潮流

风格：网络感、抽象、有梗、反差、个性。

重点：

- 网络用语
- 日常口语
- 动物与人物组合
- 反差表达
- 谐音和叠字
- 短句式 ID

不要把所有网络词都视为高质量素材，必须进行语义和质量审核。

### 6. 海都潮人

这是唯一明确保留 2～3 个汉字作为主要输出长度的风格。

风格：

- 简洁、利落、时髦
- 有辨识度
- 有一点抽象和个性
- 中性、冷感、街头感
- 避免传统网游古风
- 避免明显随机拼字感
- 不要过度萌化

重点使用：

- 高频但不俗套的单字
- 现代感双字词
- 适合首位的前缀
- 适合尾位的后缀
- 有反差感的组合

允许从更长的原始名称中提取素材，但最终生成仍以 2～3 字为主。

## 四、单字、双字、三字及长短语提取

建立分层词库。

### A. 单字库

从全部合格名称中提取单字。

字段：

- text
- frequency
- uniqueNameCount
- firstCount
- middleCount
- lastCount
- positionTags
- semanticTags
- styleTags
- confidence
- enabled

分级：

- CORE
- EXTENDED
- RARE
- SPECIAL

### B. 双字词库

来源：

- 原始两字名称
- 三字名称的相邻片段
- 四字及更长名称中的连续双字片段

分别记录来源频率，不要把不同来源简单混为一个数值。

### C. 三字词库

来源：

- 原始三字名称
- 四字及更长名称中的连续三字片段
- 有完整语义的三字短语

### D. 四字及更长短语库

提取：

- 四字完整短语
- 五字和六字短语
- 更长名称中有独立意义的语义片段

必须识别词语边界，不要将所有连续字符组合都误判为词语。

### E. 叠字库

独立识别：

- AA
- AAX
- XAA
- AAA
- 其他有实际命名价值的重复结构

### F. 组合关系库

建立词语之间的关系：

- 前缀关系
- 后缀关系
- 修饰关系
- 主谓关系
- 动宾关系
- 并列关系
- 叠字关系
- 意象关联

对不确定的关系标记为待审核，不要强行判断。

## 五、位置偏好与位置标签

必须针对不同长度分别计算位置分布。

两字：
- FIRST
- LAST

三字：
- FIRST
- MIDDLE
- LAST

四字及以上：
- FIRST
- SECOND
- INTERNAL
- PENULTIMATE
- LAST

同时计算：

- 绝对位置频率
- 相对位置频率
- 不同长度下的位置偏好
- 位置倾向置信度

位置标签：

`FIRST`、`MIDDLE`、`LAST`、`FREE`。

统计规则：

- 样本量不足时标记 LOW_CONFIDENCE。
- 样本量达到 20 且某位置占比达到 62% 时，可标记明显位置倾向。
- 不同名称长度不能直接混合计算位置占比。
- 位置倾向只影响生成权重，不应变成绝对限制。

另外识别：

`SURNAME_CANDIDATE`

用于标记疑似姓氏型首字，但不得仅凭首位出现频率就认定为姓氏。

双字词也需要位置属性，例如：

- 可独立使用
- 适合前缀
- 适合中间
- 适合后缀
- 自由组合

## 六、权重和质量系统

不能直接使用原始词频作为最终生成权重。

综合考虑：

1. 出现频率
2. 不同玩家覆盖数
3. 位置适配程度
4. 词语完整性
5. 语义质量
6. 风格匹配度
7. 组合重复率
8. 样本可信度
9. 人工审核结果

统计权重和人工风格权重必须分开保存。

支持：

- 自然频率模式
- 均匀随机模式
- 风格优先模式
- 低重复模式
- 长尾探索模式

为不同风格建立独立的长度策略。

海都潮人：
- 主要生成 2～3 字。

萌系日常：
- 2～6 字为主。

自然意象：
- 2～6 字为主，可扩展。

清冷文艺：
- 2～6 字为主，可扩展短句。

- 2～6 字为主，允许更长名称。

趣味潮流：
- 2～6 字为主，支持短句式组合。

以上都是建议的生成范围，允许用户自行调整。

生成器应根据长度自动选择：

- 可用词库
- 字符位置权重
- 短语组合规则
- 风格权重
- 去重策略

不要简单地把单字库随机拼接成名字。

## 十、数据质量

重点避免：

- 重复名称造成频率虚高
- 不同长度位置统计混淆
- 繁简体混淆
- 无意义连续片段进入词库
- 错误的语义分类
- 低频字被错误标记为高频
- 位置倾向变成绝对限制
- 生成结果大量重复
- 不同风格词库高度重叠
- 长名称被机械拆分导致词义丢失

审核状态：

- AUTO
- PENDING
- APPROVED
- REJECTED
